# ServerHub

Панель управления несколькими серверами: сайт на Vercel, база в Supabase и лёгкий агент на каждом устройстве. Агент работает в Termux (Android), Linux, macOS и Windows.

Устройства могут находиться за роутером, поэтому связь идёт только от агента наружу:

```text
Агент ── HTTPS, раз в 10 с ──▶ Vercel (сайт и API) ──▶ Supabase (Postgres)
      ◀── очередь команд ─────
```

В одном запросе агент отправляет метрики и получает команды своего сервера. Метрики, команды и история хранятся отдельно для каждого сервера.

## Структура проекта

```text
ServerHub/
├─ README.md
├─ supabase/schema.sql      таблицы, функции, права, автоочистка

│  ├─ platform.js           определение операционной системы
│  ├─ collectors.js         сбор метрик

│  ├─ process-runner.js     запуск программ без shell
│  ├─ config.js             чтение .env
│  ├─ ecosystem.config.js   настройки pm2

│  ├─ test/                 тесты: npm test
│  └─ .env.example
└─ web/                     сайт на Next.js
   ├─ vercel.json
   ├─ .env.example
   └─ src/
      ├─ app/               страницы и API
      ├─ components/        интерфейс
      ├─ hooks/             опрос данных
      └─ lib/               авторизация, база, zod-схемы
```

## Что понадобится

- Компьютер с Git и Node.js 20 или новее
- Бесплатные аккаунты [GitHub](https://github.com), [Supabase](https://supabase.com) и [Vercel](https://vercel.com)

## Шаг 0. Сгенерируйте секреты

Выполните на компьютере команду. Результат будет значением `SESSION_SECRET`:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Придумайте ещё `ADMIN_PASSWORD` — пароль для входа на сайт, не короче 12 символов.

`AGENT_KEY` вручную создавать не нужно: панель выдаёт отдельный ключ каждому серверу (шаг 4).

## Шаг 1. Загрузите проект на GitHub

Создайте на GitHub пустой репозиторий `ServerHub` и выполните в папке проекта:

```bash
git init
git add .
git commit -m "ServerHub"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ServerHub.git
git push -u origin main
```

Файлы `.env` исключены через `.gitignore`, секретов в коде нет.

## Шаг 2. Создайте базу в Supabase

1. Откройте [supabase.com/dashboard](https://supabase.com/dashboard) и нажмите **New project**.
2. Укажите название и пароль базы. В поле **Region** выберите **Frankfurt (eu-central-1)**.
3. Дождитесь, пока проект будет создан.
4. Откройте **SQL Editor** и нажмите **New query**.
5. Вставьте всё содержимое файла `supabase/schema.sql` и нажмите **Run**. Должно появиться сообщение **Success**.
6. В **Table Editor** проверьте, что есть таблицы `servers`, `server_state`, `metrics`, `commands`, `login_attempts`.
7. Скопируйте два значения из **Project Settings** (названия разделов в Supabase иногда меняются):
   - **Project URL** — это `SUPABASE_URL`;
   - секретный ключ `sb_secret_...` или старый `service_role` — это `SUPABASE_SERVICE_KEY`.

Секретный ключ даёт полный доступ к базе. Он должен храниться только в Vercel.

**Проверка автоочистки.** Выполните в SQL Editor:

```sql
select jobname, schedule from cron.job;
```

В результате должна быть строка `serverhub-cleanup`. Если расширение недоступно, старые данные всё равно будет удалять API сайта.

## Шаг 3. Разверните сайт на Vercel

1. На [vercel.com/new](https://vercel.com/new) импортируйте репозиторий `ServerHub`.
2. В поле **Root Directory** нажмите **Edit** и выберите папку `web`. Это обязательно.
3. Откройте **Environment Variables** и добавьте четыре переменные:

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | Project URL из шага 2 |
| `SUPABASE_SERVICE_KEY` | секретный ключ из шага 2 |
| `ADMIN_PASSWORD` | пароль для входа, не короче 12 символов |
| `SESSION_SECRET` | значение из шага 0, не короче 32 символов |

4. Нажмите **Deploy** и дождитесь завершения.
5. Откройте адрес вида `https://ваш-проект.vercel.app` и войдите с паролем.

Если вы выбрали для Supabase не Франкфурт, укажите близкий регион Vercel в `web/vercel.json`. Так сайт будет отвечать быстрее и расходовать меньше лимитов.

## Шаг 4. Добавьте сервер на сайте

1. Нажмите **Добавить сервер** и введите название.
2. Панель покажет три строки: `BACKEND_URL`, `SERVER_ID` и `AGENT_KEY`.
3. Скопируйте их и сохраните в менеджере паролей.

**Ключ показывается только один раз.** В базе хранится только его хэш, восстановить ключ нельзя. Если ключ потерян, добавьте сервер заново под другим названием, а старую запись удалите (см. раздел «Как удалить сервер»).

Для каждого устройства создавайте отдельный сервер со своим ключом.

## Шаг 5. Установите агента

Выберите свою систему. Агент сам определит её при запуске.

| Система | Батарея | Автозапуск |
|---|---|---|
| Android (Termux) | `termux-battery-status` | Termux:Boot |
| Linux, VPS | `/sys/class/power_supply`, если батарея есть | `pm2 startup` |
| macOS | `pmset`, если батарея есть | `pm2 startup` |
| Windows | `Win32_Battery`, если батарея есть | Планировщик заданий |

Если у устройства нет батареи, панель скрывает её карточку и график. На обычном VPS это нормально.

**Приватный репозиторий.** Для `git clone` создайте токен в GitHub: **Settings → Developer settings → Fine-grained tokens**, только для этого репозитория, с правом **Contents: Read-only**. Перед клонированием выполните команду ниже, а при запросе пароля вставьте токен:

```bash
git config --global credential.helper store
```

Без сохранённого токена кнопка «Обновить из GitHub» не сработает: агент не может вводить пароль. Токен хранится на устройстве открытым текстом в `~/.git-credentials`, поэтому давайте ему только право на чтение.

### Android (Termux)

**1. Приложения.** Установите из **F-Droid** приложения **Termux**, **Termux:API** и **Termux:Boot**.

Все три должны быть из одного источника, потому что у сборок разные подписи. Если Termux установлен с GitHub, то Termux:API и Termux:Boot тоже берите из разделов Releases на GitHub ([termux-api](https://github.com/termux/termux-api/releases), [termux-boot](https://github.com/termux/termux-boot/releases)). Termux из Google Play удалите и поставьте заново из F-Droid.

Откройте **Termux:Boot** один раз, чтобы Android разрешил автозапуск.

**2. Настройки Android.**

- Для Termux и Termux:API выключите экономию батареи: **Настройки → Приложения → Termux → Батарея → Без ограничений**.
- Чтобы видеть имя Wi-Fi, разрешите приложению Termux:API доступ к геолокации. Без него панель покажет «недоступно», остальное будет работать.
- **Android 14 и новее:** в разделе «Для разработчиков» включите **Disable child process restrictions**.
- **Android 12 и 13:** система может завершать фоновые процессы. Подключите телефон к компьютеру с ADB и выполните:

```bash
adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent"
adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"
adb shell settings put global settings_enable_monitor_phantom_procs false
```

**3. Установка.**

```bash
pkg update -y && pkg upgrade -y
pkg install -y nodejs git termux-api nano
npm install -g pm2

# Проверка: команда должна вывести JSON с данными батареи
termux-battery-status

git clone https://github.com/ВАШ_ЛОГИН/ServerHub.git ~/ServerHub
cd ~/ServerHub/agent
cp .env.example .env
nano .env
```

Заполните `BACKEND_URL`, `SERVER_ID` и `AGENT_KEY` значениями из шага 4 и сохраните файл (`Ctrl+O`, `Enter`, `Ctrl+X`).

**4. Запуск.**

```bash
termux-wake-lock
pm2 start ecosystem.config.js
pm2 save
pm2 logs serverhub-agent --lines 20 --nostream
```

В логах должна быть строка `[agent] запущен: termux`.

**5. Автозапуск после перезагрузки.**

```bash
mkdir -p ~/.termux/boot
cp ~/ServerHub/agent/boot/start-agent.sh ~/.termux/boot/
chmod +x ~/.termux/boot/start-agent.sh
```

### Linux и VPS

Команды приведены для Debian и Ubuntu. Нужен Node.js 18.15 или новее.

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs git
sudo npm install -g pm2

git clone https://github.com/ВАШ_ЛОГИН/ServerHub.git ~/ServerHub
cd ~/ServerHub/agent
cp .env.example .env
nano .env
```

Заполните `BACKEND_URL`, `SERVER_ID` и `AGENT_KEY`, затем запустите агента:

```bash
chmod 600 .env
pm2 start ecosystem.config.js
pm2 save
pm2 logs serverhub-agent --lines 20 --nostream
```

В логах должна быть строка `[agent] запущен: linux`.

Для автозапуска выполните следующую команду. Она выведет ещё одну команду с `sudo`, скопируйте и выполните её, а потом снова сделайте `pm2 save`:

```bash
pm2 startup
```

Запускайте агента от того же пользователя, под которым работают ваши проекты в pm2, иначе панель их не увидит.

**macOS.** Установка такая же: поставьте Node.js и Git, например через Homebrew (`brew install node git`), затем выполните те же команды.

### Windows

Установите [Node.js LTS](https://nodejs.org) и [Git для Windows](https://git-scm.com/download/win). Затем откройте **PowerShell**.

В PowerShell используйте именно `npm.cmd` и `pm2.cmd`. Обычные `npm` и `pm2` могут быть заблокированы политикой запуска скриптов.

```powershell
npm.cmd install -g pm2

git clone https://github.com/ВАШ_ЛОГИН/ServerHub.git $HOME\ServerHub
cd $HOME\ServerHub\agent
Copy-Item .env.example .env
notepad .env
```

Заполните `BACKEND_URL`, `SERVER_ID` и `AGENT_KEY` и сохраните файл. Затем запустите агента:

```powershell
pm2.cmd start ecosystem.config.js
pm2.cmd save
pm2.cmd logs serverhub-agent --lines 20 --nostream
```

В логах должна быть строка `[agent] запущен: windows`.

Если pm2 установлен не в стандартную папку `%APPDATA%\npm`, укажите в `.env` путь к его файлу:

```ini
PM2_SCRIPT=D:\tools\node_modules\pm2\bin\pm2
```

Для автозапуска откройте PowerShell **от имени администратора** и выполните:

```powershell
schtasks /Create /TN "ServerHub Agent" /SC ONLOGON /TR "$env:APPDATA\npm\pm2.cmd resurrect"
```

Агент запустится при входе пользователя в систему.

### Подключение ваших проектов

Панель показывает всё, что запущено в pm2 на этом устройстве:

```bash
cd ~/my-project
pm2 start index.js --name my-project
pm2 save
```

В PowerShell вместо `pm2` используйте `pm2.cmd`. После добавления или удаления проекта всегда выполняйте `pm2 save`, иначе после перезагрузки список будет старым.

## Шаг 6. Проверьте, что всё работает

1. `pm2 list` на устройстве показывает `serverhub-agent` со статусом `online`.
2. В списке серверов на сайте рядом с названием указано «онлайн», время ответа не превышает 10–15 секунд.
3. В шапке указана правильная система, заполнены карточки RAM, хранилища, CPU и задержки.
4. Через минуту на графике за 1 час появятся первые точки.
5. Нажмите **Логи** у любого проекта: окно должно показать вывод.
6. Нажмите **Перезапустить** у тестового проекта: появится запись в «Истории команд» и уведомление.
7. Отключите сеть на устройстве: через 30 секунд панель покажет **Оффлайн**. Включите сеть обратно.
8. Перезагрузите устройство и убедитесь, что агент запустился сам.
9. Если серверов несколько, переключитесь на другой и убедитесь, что проекты и история у него свои.

## Как удалить сервер

Выполните в SQL Editor, подставив название. Вместе с сервером удалятся его метрики и команды:

```sql
delete from public.servers where name = 'Название сервера';
```

Затем остановите агента на устройстве: `pm2 delete serverhub-agent` и `pm2 save`.

## Если что-то не работает

| Что видно | Что сделать |
|---|---|
| В логах агента `Сервер отклонил SERVER_ID или AGENT_KEY (401)` | Проверьте значения в `agent/.env`: они должны быть от одного и того же сервера |
| Агент сообщает, что не задан или неверен `SERVER_ID` | Заполните `.env` строками из окна «Добавить сервер» |
| В логах агента `Сервер ответил 500` | Откройте логи функции в Vercel. Чаще всего неверно указаны `SUPABASE_URL` или ключ либо не выполнен `schema.sql` |
| Сайт сообщает «Внутренняя ошибка сервера» при входе | Не задана переменная или она короче минимальной длины |
| Нет карточки батареи на телефоне | Установите приложение Termux:API и пакет `termux-api`, проверьте `termux-battery-status` |
| Пустой список проектов | Выполните `pm2 list` от того же пользователя и убедитесь, что проекты запущены |
| Windows: нет проектов, хотя pm2 работает | Укажите в `.env` путь `PM2_SCRIPT` |
| Windows: `не удаётся загрузить файл pm2.ps1` | Используйте `pm2.cmd` и `npm.cmd` |
| Агент пропадает при выключенном экране телефона | Проверьте `termux-wake-lock`, экономию батареи и настройки Android |
| «Источник: По процессам pm2» в карточке CPU | На этой версии Android нет данных о нагрузке системы. Показана суммарная нагрузка процессов pm2, без учёта остальных приложений |
| Логи показывают 200 строк | `pm2 logs --lines 100` выводит по 100 строк из stdout и stderr, это штатное поведение |

## Лимиты бесплатных тарифов

**Каждый агент расходует лимиты отдельно**, это главное ограничение при нескольких серверах.

- **Vercel Hobby:** 1 млн вызовов функций и 4 часа Active CPU в месяц. При превышении функции останавливаются до конца 30-дневного периода.
- Открытая вкладка панели делает примерно **1 200** запросов в час. Скрытая вкладка запросов не делает.
- **Supabase Free:** 500 МБ базы и 5 ГБ трафика в месяц. История за 7 дней — примерно 60 тысяч коротких строк на сервер при интервале 10 с.

Запросов от агентов в месяц:

| Серверов | Интервал 10 с | Интервал 25 с |
|---|---|---|
| 1 | 259 тыс. | 104 тыс. |
| 2 | 518 тыс. | 207 тыс. |
| 3 | 778 тыс. | 311 тыс. |
| 5 | 1,3 млн (больше лимита) | 518 тыс. |
| 8 | 2,1 млн (больше лимита) | 829 тыс. |

Лимит Active CPU может закончиться раньше лимита запросов. Первые дни проверяйте расход в **Vercel → Usage**. Чтобы изменить интервал:

```bash
cd ~/ServerHub/agent
nano .env        # SYNC_INTERVAL_SEC=20
pm2 restart serverhub-agent
```

Допустимый интервал — от 3 до 25 секунд. Верхняя граница нужна, чтобы панель не показывала ложный статус «Оффлайн», он включается через 30 секунд без данных.

Чем больше интервал, тем дольше команда идёт до сервера: она ждёт очередного запроса агента. Команды старше 60 секунд не выполняются.

## Безопасность

- Все секреты сайта хранятся только в переменных окружения.
- У каждого сервера свой ключ. В базе лежит только его SHA-256, сам ключ показывается один раз.
- Агент может получать и завершать только команды своего сервера.
- Сессия хранится в подписанной httpOnly-куке. Чтобы завершить все сессии, смените `SESSION_SECRET`.
- Попытки входа ограничены: 5 за 15 минут с одного адреса, затем блокировка на 15 минут.
- Таблицы и функции в Supabase закрыты для публичных ключей. Обращаться к ним может только сервер Vercel.
- Агент выполняет только `start`, `stop`, `restart`, `update` и `logs`. Имя проекта проверяется по свежему `pm2 jlist`, программы запускаются через `execFile` без shell.
- Агента нельзя остановить из панели, иначе пропадёт удалённое управление.
- Переменные окружения ваших проектов агент никуда не отправляет.

Что важно учитывать:

- Кнопка «Обновить из GitHub» запускает код из репозитория проекта, включая скрипты `npm install`. Подключайте только репозитории, которым доверяете, и защитите свой аккаунт GitHub двухфакторной аутентификацией.
- Логи проектов хранятся в базе 7 дней. Не выводите в логи пароли и токены.

```bash
# Тесты агента
cd agent
npm test

# Сайт локально: заполните web/.env.local по образцу web/.env.example
cd web
npm install
npm run dev
```

Чтобы обновить агента, нажмите **Обновить из GitHub** в его карточке или выполните `git pull` и `pm2 restart serverhub-agent`.
